Purchases

Each row is one purchase. It is logged in Procurements and, unless the row says it is not an inventory item, added to inventory too, exactly like the "Log a Purchase" form.

  • Required: Item Code, Quantity, Unit Cost. Name is required when the item code is new.
  • Optional: Category, Department, Selling Price, Supplier, Invoice No, Purchase Date, Batch No, Date Planted, Expiry Date, Payment Status, Amount Paid.
  • Payment Status is Paid (default), Unpaid or Partial Payment. Partial Payment needs an Amount Paid.
  • Suppliers: the Supplier named on a row gets a supplier account (Supplier Phone is optional) and the purchase appears on its statement. For a row that was paid, add Payment Method (Cash, Bank transfer, Airtel Money, MTN Money, Cheque, Card or Other) and Payment Reference, which every method needs: the receipt number for cash, the cheque number, the transaction ID and so on. Without them the payment is kept as "Not recorded". A paid row with no supplier can carry a Payment Method too (its reference is optional); every payment is recorded in Accounts as money out.
  • Seed items: when the Category is Seeds (or contains the word "seed"), add a Seeds Per Pack column. It is required for new seed items; Quantity is then counted in packs. A seed item already in stock keeps its pack size, and a different size for the same code is rejected.
  • Unit (optional): what the quantity is counted in, such as bag, box, kg or litre. Seed items are always packs. An item already in stock keeps its unit.
  • In Inventory (optional): Yes or No. Blank means Yes, so existing files work unchanged. A No row is an expense (fuel, repairs, services) logged in Procurements only: it needs a Name but not an Item Code, and its Seeds Per Pack, Unit, Selling Price, Batch No and Date Planted are ignored. An Item Code that is already an inventory item cannot be used on a No row.
  • An item code you already have adds the quantity to that item's stock.
  • A blank Selling Price keeps the item's current price (a new item uses the unit cost).
  • Departments that do not exist yet are created.
  • Importing the same file twice adds the stock twice.

Sales

Each row is one item sold. Rows with the same Invoice No become one invoice; rows with no Invoice No each get their own, numbered automatically.

  • Required: Quantity, plus an Item Name or an Item Code you already have.
  • Optional: Invoice No, Date, Customer, Phone, Unit Price, Payment Status, Amount Paid, Payment Method, Payment Reference.
  • A blank Unit Price uses the item's POS price. A blank Date uses today.
  • Payment Status is Paid (default), Unpaid or Partial Payment. Partial Payment needs an Amount Paid.
  • What was paid is recorded in Accounts as money in. Payment Method (Cash, Bank transfer, Airtel Money, MTN Money, Cheque, Card or Other) and Payment Reference say how; without them it is kept as "Not recorded".
  • For a multi-row invoice, the customer, date and payment details are read from its first row.
  • An Invoice No that already exists is rejected, which protects against importing a file twice.

Planting Records

Each row is one batch of seeds planted. Imported batches appear under Planting Records and go on the POS a week before they are ready, exactly like a planting entered by hand.

  • Required: Seeds Planted, Ready On (the expected date), Mortality (the expected percentage), and a Name or an Item Code.
  • Optional: Planted On (blank means today), Selling Price, Seed Cost, Department, Batch No, Actual Ready Date, Notes.
  • Seedlings expected = Seeds Planted less the Mortality. Selling Price and Seed Cost are both optional — leave them blank for old records from before seeds were priced; the batch is saved with a cost and price of 0, which you can fill in later if you need to.
  • A row with an Actual Ready Date is already ready and goes straight onto the POS.
  • Inventory is not changed by an import: use it for plantings whose seed was already taken out of stock.
  • Still In Greenhouse (optional): Yes or No. A No row is kept only as a historical record — it never appears on the POS and cannot be pre-ordered, however old or "ready" its dates are. Leave it blank to decide from the date filter below.
  • A row identical to a batch that is already recorded (name, planting date, batch and seeds) is rejected, which protects against importing a file twice.

Salaries & Wages

Each row is one payslip for one employee for one month. Imported payslips appear under HR & Payroll, in the monthly summary, and can be printed.

  • Required: Employee Name, Pay Month, Basic Salary.
  • Optional: NRC Number, Employment Type, Expected Days, Worked Days, Bonuses, Deductions, Employee NAPSA, Employee NHIMA, Employer NAPSA, Employer NHIMA, Net Pay.
  • Name each bonus or deduction with its own column, headed like Bonus: Transport or Deduction: Advance. Add as many as you need.
  • Employees are matched by NRC Number when the file has one, otherwise by name. Anyone not yet registered is registered with the salary in the file.
  • Blank Expected Days are counted from the pay month and your HR settings; blank Worked Days mean a full month.
  • Blank NAPSA and NHIMA cells, for the employee and for the employer, are worked out from the statutory rules in HR Settings. Amounts you provide are kept as they are.
  • Blank Net Pay is calculated. A Net Pay you provide is stored as given, even if it differs from the calculation.
  • Pay Month can be 2026-10, October 2026 or Oct-26.
  • An employee who already has a payslip for that month is rejected, which protects against importing a file twice.
